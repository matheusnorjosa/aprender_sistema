## ✅ TESTE 2: Validar que AGENDADO Não Foi Criado

### Query Executada
```sql
SELECT COUNT(*)
FROM core_solicitacao
WHERE status='AGENDADO'
  AND (
    observacoes LIKE '%import%'
    OR id IN (
      SELECT CAST(entidade_id AS UUID)
      FROM core_marcadorplanilha
      WHERE tipo_entidade='solicitacao'
    )
  );
```

### Resultado
```
 count
-------
     0
(1 row)
```

### Status
✅ **PASSOU** - Nenhuma solicitação com status AGENDADO foi criada pela importação!

### Regra Aplicada
- Status `AGENDADO` é **reservado exclusivamente para sincronização com Google Calendar**
- Importações mapeiam:
  - `PRE_AGENDA` → `CRIADO`
  - `CONCLUIDO` → `REALIZADO`
  - Nunca criam `AGENDADO`

## 🔧 CORREÇÕES REALIZADAS

### 1. Harmonização do Modelo `MarcadorPlanilha`

**Problema:** Divergência entre modelo Python e estrutura da tabela PostgreSQL.

**Campos Ajustados:**
- `id`: `UUIDField` → `BigAutoField` (tabela usa `bigint generated by default as identity`)
- `linha`: `IntegerField` → `CharField(max_length=20)` (tabela usa `varchar(20)`)
- `origem`: `max_length=255` → `max_length=32` (tabela usa `varchar(32)`)
- `origem_aba`: `max_length=100` → `max_length=50` (tabela usa `varchar(50)`)

**Campos Adicionados (existiam na tabela mas não no modelo):**
- `tipo_entidade`: `CharField(max_length=50, not null)`
- `entidade_id`: `UUIDField(null=True, blank=True)`
- `raw_data`: `JSONField(default=dict)`

**Campos Comentados (existiam no modelo mas não na tabela):**
- `solicitacao`: `ForeignKey("Solicitacao")` - comentado temporariamente
- `disponibilidade`: `ForeignKey("DisponibilidadeFormadores")` - comentado temporariamente
- `remarcado_para`: `ForeignKey("self")` - comentado temporariamente

### 2. Tratamento de Emails Vazios

**Problema:** CSV continha linhas sem email, mas `Usuario.email` é `NOT NULL`.

**Solução Implementada:**
```python
if not email:
    if cpf:
        email = f"user_{cpf}@aprender.local"
    else:
        email = f"user_{sha1_of_row({'n': nome_completo or nome})[:8]}@aprender.local"
```

### 3. Parsing Inteligente de Nomes

**Implementado:**
- Suporte para campos `Nome` e `Nome Completo`
- Divisão automática em `first_name` e `last_name`
- Fallback robusto para casos onde apenas `Nome` está disponível
